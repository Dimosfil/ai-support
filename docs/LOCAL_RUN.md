# Локальный запуск

Требуется Node.js 24.14.1 или новее в ветке 24.x. Внешних npm-зависимостей нет.
Команды PowerShell из корня проекта:

```powershell
npm.cmd run dev:setup
npm.cmd start
```

Setup создаёт `.local/runtime.json`, `.local/identities.json` с хешами ключей
и `.local/access.txt` с двумя случайными ключами user/operator. Существующие файлы
не перезаписываются. Файлы `.local/` и `data/` исключены из Git. Ключи не выводятся
в журнал setup. Откройте `.local/access.txt` локально в редакторе, не публикуйте файл.
На Windows ограничьте доступ к этой папке своей учётной записью: POSIX mode сам
по себе не настраивает Windows ACL. Это только адаптер разработки.

Адрес берётся из `.local/runtime.json`, исходно `http://127.0.0.1:4317`.
Конфликт порта останавливает запуск; другой порт автоматически не выбирается.
В браузере откройте этот адрес и введите ключ user; создайте обращение. В другой
вкладке войдите как operator, возьмите обращение, ответьте, добавьте заметку,
измените статус. Обновите пользовательскую вкладку: заметка там отсутствует.
Telegram и внешние уведомления для этого сценария не нужны.

Ключ браузер держит только в памяти страницы. Черновики и незавершённые запросы
лежат в sessionStorage текущей вкладки, отдельно по tenant/subject/role. После
перезагрузки потребуется повторный вход; черновик той же identity восстановится.
Если браузер запрещает storage, форма работает, но сохранность черновика при
перезагрузке не гарантируется. Данные черновиков не отправляются в диагностику.
Явный выход очищает черновики и pending-запросы текущей identity. Закрытие вкладки
обычно также удаляет sessionStorage; это не долговременный backup.

При потере ответа повторная отправка сохраняет исходный ключ. Если текст уже
изменён, сначала подтверждается результат прежней отправки, новый текст остаётся
черновиком. При конфликте версии нажмите «Обновить», проверьте переписку и
отправьте актуальный ответ. Обновление истории выполняется вручную.

## Настройки

`SUPPORT_CONFIG` может указать другой JSON-файл. Все относительные пути в JSON
считаются от текущей рабочей папки; на границе I/O преобразуются в абсолютные.
Источник начальных значений: `config/support.example.json`.

- `host` — только loopback (`127.0.0.1` или `::1`) для локального identity-адаптера.
- `port` — обязательный фиксированный порт 1–65535.
- `dataDirectory` — выделенный каталог состояния приложения; SQLite-файл
  `support.sqlite` и его WAL/SHM. Не указывайте каталог чужого продукта.
- `identitiesFile` — закрытый JSON-массив `{tenant,subject,role,tokenHash}`.
  tokenHash — SHA-256 случайного ключа достаточной длины. Файл загружается при
  старте; изменения и отзыв ключей требуют перезапуска стенда.
- `requestBytes`, `requestsPerMinute` — предел тела и входящих запросов по IP.
- `policy` — `subjectLength`, `messageLength`, `writesPerMinute` для ядра.

Некорректная обязательная конфигурация останавливает старт. Отсутствие настроек
Telegram, diagnostics и доставки не мешает ядру: эти возможности выключены.
`delivery.enabled=true` включает worker через доверенный серверный
`delivery.adapterModule`; контракт и инструкция — [NOTIFICATIONS.md](NOTIFICATIONS.md).
Новая БД имеет v2; существующая v1 не обновляется автоматически. Отказ optional
адаптера выключает только доставку с обезличенным сообщением. При shutdown
runtime дожидается worker до закрытия SQLite.
Стенд не подключает config-service и внешние сервисы. Остановка: Ctrl+C.
Не копируйте работающий SQLite-файл без WAL как backup. Миграция G2.2 создаёт
согласованный backup; постоянная production backup/retention-процедура ещё
должна быть определена и проверена перед эксплуатацией (G4).

## Проверка

```powershell
npm.cmd test
git diff --check
```

Тесты поднимают кратковременные HTTP-серверы на loopback с автоматически выбранным
ОС портом, используют временные SQLite-файлы и синтетические identity и удаляют
своё состояние. Реальные ключи и внешние сервисы не используются.
Проверяются изоляция, Unicode readback, заметки, идемпотентность, версии,
rollback, переоткрытие БД, лимиты, HTTP-сценарии и повтор отправки браузера.
Визуальная проверка страницы и подключение реального продукта ещё не выполнены.
